## EnQuote — Release Notes

### New Features
- **Auto-Drafter [beta].** A new top-level tab that imports Salesforce's "Quote Request Cases with Case Comments" report (one-click, via the same proven Salesforce import already used elsewhere) and auto-generates a priced draft quote directly from each case's `O&M_QUOTE_REQUEST` comment — site info, findings, scope of work, labor/travel estimates, and line items (products, services, additional materials) all parsed automatically. Only cases whose O&M Status is "Quote Requested," whose case Status isn't "Closed," and whose comment contains a genuine quote-request marker are shown.
- **Send to Quotes.** A generated draft can be reviewed, manually edited, and sent to the real Quotes tab with one click — creates an authentic `Q-####` quote number (identical format to a normally created quote) and a real, standard quote record. Once sent, the draft is marked permanently and can no longer be edited from Auto-Drafter.
- **Manual line-item editing in Auto-Drafter.** Site fields, line items (name/qty/unit price, with live total recalculation), scope of work, and notes are all editable before sending to Quotes.
- **Fuzzy "Find in Catalog" picker (Auto-Drafter).** Any unmatched or low-confidence line item can be manually replaced with a real, priced catalog match via a searchable picker — tolerant of word order, partial words, and size-notation differences (e.g. `3/4"`, `3/4 in.`, `3/4in` all resolve the same way).
- **Fuzzy search on the manual Quotes page.** The "Add Items" product search (both the category-filtered and global search boxes) now tolerates word order, partial words, and size-notation differences the same way, instead of requiring an exact, single contiguous substring match.
- **Compatibility Matrix & dependency advisories.** New engine cross-checks a proposed replacement part against the equipment already on-site (when identifiable from the case's own findings text) using a verified, sourced compatibility dataset — flags incompatible or review-required pairings, and surfaces relevant accessory/dependency suggestions (Gateway, Terminator, Sealing Cap, Disconnect Tool, etc.) drawn from the full, real Product_Dependencies dataset rather than a small hand-picked subset.
- **Material & Size Consistency Check.** Flags a generated draft if its conduit-family line items mix materials (EMT vs. PVC) or sizes — validated directly against 86 real, previously approved quotes (only 1 of 28 multi-conduit-item quotes ever legitimately mixed materials).
- **"Clear Generated Drafts."** Resets all saved Auto-Drafter drafts back to a fresh, not-yet-drafted state in one action. Does not affect drafts already sent to Quotes (those are real Quote records).

### Improvements
- **Cleaner unmatched line-item display.** An item the engine couldn't confidently match to the catalog now shows its own clean requested name (e.g. "Suntech STP370S-B60/Wnhb Solar Module") instead of a verbose "Miscellaneous \<category\> (unmatched: \"...\")" wrapper, with a shorter, non-redundant review note underneath.
- **"Not in Catalog" badge.** Replaces the generic "low" confidence label specifically (and only) for genuinely unmatched items, so it's immediately clear why an item needs review.
- **"Service Type" now shown on generated drafts**, sourced from the case's own parsed Quote Category, and carried through to the real quote record when sent to Quotes.
- **Auto-Drafter's page layout** now matches the Quotes page's own structure (header, filter card, unwrapped case grid) for visual consistency.
- **Duplicate case handling.** A case with more than one Salesforce comment (normal comment history, not corrupted data) now shows exactly one tile — the most recent comment — instead of one tile per comment.
- **Background refresh no longer blanks the Auto-Drafter grid** on ordinary window-focus changes; a short throttle also prevents redundant back-to-back refreshes.

### Fixes
- **Quote-editing reset bug.** Editing an existing quote's details could get silently wiped mid-edit and reset back to the last-saved values — root-caused to the edit form re-syncing from a background data refetch (e.g. on window refocus) instead of only on genuine initial load. The form now initializes once per quote and is never overwritten by an in-flight refetch of the same quote.
- **Auto-Drafter parser: bullet-point and mojibake formatting.** A case comment using bullet-point formatting (a genuine "•" character, or a "?" character substituted for a bullet during export — both confirmed on real cases) previously caused every field in that case to silently fail to parse, producing a completely empty draft. Both variants are now stripped correctly before parsing.
- **Range-quantity parsing.** A requested quantity written as a range (e.g. "20-40 ft" or "3 to 4 hours") was previously mangled into a single incorrect number (e.g. 2,040) by naive digit-concatenation. Ranges are now detected and resolved to their upper bound, with a visible review note.
- **Size-notation matching.** The exact same physical size written different ways (`1"`, `1 in.`, `1in`, `1inch`, `1-inch`) previously tokenized into different, non-matching values, causing genuinely correct catalog matches to be missed. All common notations now resolve consistently.
- **Auto-Drafter O&M Status filter.** Corrected a column-detection bug where the filter could silently read from the wrong (generic) Status column instead of the real O&M Status column, hiding every qualifying case.
- **Panel-matching false positive.** A requested item containing only generic words (e.g. "Solar Panel") could incorrectly match an unrelated catalog item sharing those same generic words; a match is now only trusted when at least one specific (non-generic) word actually contributed to it.

### Known limitations / follow-ups not yet included in this release
- Auto-Drafter's automatic line-item matching remains intentionally strict (exact-order, whole-word phrase matching) and does not use the same fuzzy tolerance as the manual pickers — this is a deliberate safety tradeoff, not an oversight, to avoid false-positive auto-matches.
- Product Schema Migration (unifying the priced catalog and the compatibility/dependency catalog under one shared SKU) is only partially complete — 19 of ~198 catalog items are currently SKU-tagged; the rest still rely on independent name-based lookups.
- "Service Type" is not yet displayed anywhere on the Quotes page itself — the value is carried through to the real quote record, but no display row has been added there yet.
- Auto-Drafter's parser has been validated against a broader real-case sample but not against the full historical case volume — further formatting variants may still surface with continued use.
